# Frontend — instrucciones de trabajo

- Este directorio es el repositorio privado `Universiry-frontend`, rama de integración `develop`, montado como submódulo del checkout backend para desarrollo conjunto.
- Usa Vite, React, TypeScript y SCSS. Los estilos pertenecen a componentes/capacidades; los tokens compartidos viven en `src/styles/_tokens.scss`.
- El frontend presenta y valida temprano; permisos, validación de dominio y persistencia se aplican en el backend.
- Para cada cambio: escribe pruebas AAA primero, observa RED, implementa GREEN y refactoriza. Incluye estados felices, bordes, errores y permisos visibles.
- Ejecuta `npm test`, `npm run build` y `npm run lint` antes de integrar.
- `VITE_API_TARGET` configura el destino del proxy Vite. Localmente es `http://localhost:8080`; Compose lo establece a `http://backend:8080`.
- No incluir tokens, credenciales, datos estudiantiles reales ni configuración secreta en el código, fixtures o build público. La sesión OIDC se mantiene solo en memoria/sessionStorage de la pestaña; nunca usar localStorage ni imprimir token/claims. React obtiene permisos exclusivamente de `/api/v1/me` y cada capacidad recibe solo los permisos de su propia familia; el servidor aplica la autorización final.
- La ruta `/#academia` ordena raíces por `displayOrder` del nodo, hijos por orden de relación (luego orden/código del hijo), afiliaciones por su `displayOrder` y lugares con las mismas reglas. En periodos, `academic:period:read` permite la vista administrativa de estados y `academic:period:write` habilita confirmar apertura de APPROVED y cierre de OPEN; sin lectura solo se muestran periodos OPEN. No inferir afiliaciones desde texto histórico ni conservar datos administrativos tras perder el permiso.
- Los cinco editores de prioridad de `/#academia` y los formularios de facultad raíz, lugar raíz, relaciones entre unidades/lugares y afiliaciones de programas requieren `academic:structure:read` y `academic:structure:write` de `/api/v1/me`. Con lectura se consultan tanto `/api/v1/academic-structure` (árbol efectivo a fecha institucional) como `/api/v1/admin/academic-structure` (todas las vigencias). La consola presenta afiliaciones futuras e históricas en una lista con intervalos y referencias sin mostrarlas como vigentes en el árbol. Sin lectura se muestra solo el árbol público; sin escritura se ocultan los controles de edición, aunque la API conserva autorización propia por operación. Cada cambio de orden envía el valor esperado, un nuevo entero y referencia institucional a un único PATCH auditado. Las altas raíz reutilizan validación compartida; la facultad es `FACULTY` y los lugares usan tipo explícito, sin padre. Las relaciones conectan identidades existentes con tipo de eje, orden, vigencia y referencia; el backend valida ciclos, concurrencia y solapamientos. La afiliación elige un programa de la lista pública de programas publicados, una unidad activa y un lugar activo, con orden, vigencia y referencia; usa `academic_program_affiliation` y `PROGRAM_AFFILIATED`, sin duplicar identidades ni crear tablas. Todas las escrituras usan POST auditado; no crean datos de ejemplo ni cargan valores institucionales. Tras un alta válida o un conflicto 409, la interfaz consulta nuevamente ambas vistas y nunca reintenta automáticamente la mutación. Al perder lectura se oculta la línea temporal completa inmediatamente. Ante 401/403, revalida `/api/v1/me`; los controles siguen ocultos si no se confirman ambos permisos. Sin OIDC autorizado los controles quedan ocultos.
- Abrir/cerrar periodos requiere `academic:period:write` de `/api/v1/me`. Ante 409, vuelve a consultar los periodos dentro del alcance autorizado, descarta la confirmación antigua y pide revisar el estado/calendario antes de confirmar otra vez. Ante 401/403, revalida `/api/v1/me` y suspende ese token para escritura. El servidor conserva la autoridad final.
- Abrir o cerrar un periodo cambia solo su estado: no habilita oferta de asignaturas, cupos, inscripción ni matrícula. El semestre de malla curricular es distinto del periodo académico institucional.
- Mantener separados el semestre curricular de una asignatura y el periodo académico regular/intersemestral; no crear calendarios, periodos o datos oficiales ficticios para llenar estados vacíos.
